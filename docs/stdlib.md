# The Lumen Standard Library

Every module here ships with the language and needs no installation.

## The prelude

These are available in every file with no import at all:

| Name | Meaning |
|---|---|
| `print(...)` | Write values to standard output, space-separated, with a newline |
| `len(value)` | Length of a `Str`, `List` or `Map` |
| `type(value)` | The value's type name, as a `Str` |
| `str(value)` | The value rendered as a `Str` |
| `num(value)` | Parse a `Str` as a number — returns `Result` |
| `bool(value)` | The value's truthiness |
| `assert(condition, message)` | Raise `message` unless the condition is truthy |
| `panic(message)` | Stop with a located error |
| `Ok` `Err` `Some` `None` | `Result` and `Option` constructors |
| `Result` `Option` | The enum types themselves |

Everything else lives in a `std/*` module, so the prelude stays small and
predictable.

## Conventions

Three rules hold across the whole library, and knowing them saves reading every
signature:

1. **The subject comes first.** `map(xs, f)`, `split(s, sep)`, `get(m, key)`.
   This is what makes `xs |> filter(pred) |> map(f) |> sum()` read left to right.
2. **Nothing mutates unless its name says so.** `push` and `pop` change their
   list in place; `set`, `remove`, `merge`, `sort` and `reverse` all return new
   values.
3. **Fallible operations return a `Result`; absence returns an `Option`.**
   Reading a file returns `Result`. Looking up a key returns `Option`. Neither
   ever raises for an ordinary failure.

## Notes on particular modules

### `std/list` and `std/map`

`first`, `last`, `at`, `find` and `map.get` return an `Option`, so "there wasn't
one" is a value you handle rather than a `nil` you forget about.

`len` exists both in the prelude and in these modules. Importing the module's
version shadows the prelude's; either works on the right type.

### `std/json`

`parse` returns `Result`. Its error message is Lumen's own wording rather than
the host engine's, deliberately: V8 changes its JSON error text between Node
releases, and a Lumen program's output must not depend on which Node happens to
be running it.

`stringify` renders structs as objects and enums as their variant name (or
`{variant, values}` when they carry a payload).

### `std/web`

A handler is any function from a request to a response.

A **request** is a `Map` with `method`, `path`, `query`, `headers` and `body`.
A **response** is a `Map` with `status`, `headers` and `body` — the helpers build
one for you, and returning a bare `Str` is treated as HTML.

```lumen
import { serve, page, json, notFound, escape } from "std/web"

fn handle(req) {
  if req.path == "/" {
    page(title: "Home", body: "<h1>hello</h1>")
  } else if req.path == "/health" {
    json({ ok: true })
  } else {
    notFound("<p>no ${escape(req.path)}</p>")
  }
}

serve(handler: handle, port: 3000)
```

`serve` never returns — a web server that exited on its own would be a bug.
Always use `escape` on anything a visitor supplied.

### `std/ai`

Which provider runs is decided in this order:

1. an explicit `provider:` argument
2. `LUMEN_AI_PROVIDER` in the environment
3. `ANTHROPIC_API_KEY`, then `OPENAI_API_KEY`
4. otherwise the built-in `mock` provider

The `mock` provider is deliberate, not a stub: it makes examples, tests and CI
run with no key, no network and a deterministic answer. Real credentials are
strictly opt-in.

Every call returns a `Result`, so a rate limit or a network failure is a value
you handle rather than a crash.

```lumen
import { chat, converse, message, provider } from "std/ai"

match chat(prompt: "Explain recursion in one sentence.", maxTokens: 200) {
  Ok(reply) => print(reply),
  Err(why)  => print("failed: ${why}"),
}
```

`model` defaults to `claude-opus-5` for Anthropic and `gpt-4o-mini` for OpenAI,
and `LUMEN_AI_MODEL` overrides both.

### `std/fs` and `std/http`

Both are `Result`-returning throughout. An HTTP response with a non-2xx status
is still `Ok` — the *request* succeeded; check `status` to decide what it means.
